# Brain — правила (для агента)

Узел = `projects|domains|decisions|lessons/<name>.md`. Индексируются только строки из `## Якоря`.

```
---
title: <name>
type: project | domain | decision | lesson
tags: [<name>, …]        # имя проекта обязательно в tags — по нему cwd-буст
updated: YYYY-MM-DD
confidence: high | medium | low
sources: [path, …]
---
## Суть            ≤5 строк
## Якоря           - <факт ≤240 симв> ⇒ path:line | skill <name> chNN | doc
## Куда смотреть глубже
## Связи           [[dir/node]]
```

Якорь = одно устойчивое утверждение + указатель. Без `⇒` не принимается.
Хорошие якоря: инвариант, грабли, известный баг со статусом, где живёт X.
Плохие: временный статус, мнение, то, что видно из имени файла.

Якорь — указатель, не копия. Если факт уже стабильно задокументирован в
AGENTS.md/CLAUDE.md проекта или в его skill (glossary/patterns/chapters) —
не переписывай формулировку в brain, добавь короткий якорь-ссылку
(`<тема> ⇒ AGENTS.md "Hard rules"` / `⇒ skill <name> chNN`). Полный текст
в brain — только для того, чего там ещё нет: свежий баг до фикса в
AGENTS.md, находка этой сессии, кросс-проектная связь. При обновлении
AGENTS.md/skill по факту, который уже есть якорем в brain — сверь и
поправь формулировку/статус в brain в том же заходе, не оставляй расходиться.

Куда что:
- поведение агента → SOUL.md
- ≤1 строки, нужно каждый turn → MEMORY.md / USER.md
- процедура «как сделать» → skill; полный текст модуля → project-skill chapters
- компетенции пользователя, стандарт↔код → LEARNING_MAP.md
- всё остальное устойчивое о проекте/домене → сюда

CLI `~/.hermes/brain/bin/brain`: `new <type> <name>` · `add <dir/node> "…⇒…"` (подтверждённое) ·
`inbox <dir/node> "…⇒…"` (кандидат) · `review` · `search "…"` · `lint` · `index`.
Инъекция: ≤5 якорей, ≤700 симв., буст узлу с тегом = проект из cwd.
